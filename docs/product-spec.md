# Берік Тұлға

Мобильное приложение для формирования привычки раннего подъёма, утренней зарядки, ходьбы и спорта через игровую механику захвата территории на реальной карте.

Главная идея:

**Реальная физическая активность пользователя превращается в игровую территорию на карте города.**

Пользователь выходит утром на прогулку или пробежку, приложение отслеживает GPS-маршрут и шаги. При замыкании маршрута территория внутри контура захватывается пользователем и его командой.

Механика вдохновлена:

- Slither.io
- Paper.io
- Strava
- Pokémon GO

Но приложение должно иметь собственную визуальную идентичность и механику.

---

# 1. Название

**Берік Тұлға**

Основной слоган:

**Қадам бас. Аумақты иелен. Өзіңді жең.**

Альтернативный вариант:

**Оян. Қозғал. Жеріңді ал.**

---

# 2. Основная цель MVP

Создать мобильное приложение, в котором пользователь может:

1. зарегистрироваться;
2. вступить в команду;
3. открыть карту города;
4. начать прогулку или пробежку;
5. отслеживать GPS-маршрут;
6. считать шаги;
7. замыкать маршрут;
8. захватывать территорию внутри маршрута;
9. видеть территории других команд;
10. соревноваться по площади и количеству шагов;
11. поддерживать ежедневную серию активности.

Для первого MVP не нужно создавать полноценную фитнес-экосистему.

Главный продуктовый цикл:

**Проснулся → вышел → прошёл маршрут → захватил территорию → усилил команду → вернулся завтра.**

# 9. Механика захвата территории

Это главная функция приложения.

Не хранить весь город как один большой polygon.

Разбить карту на небольшие игровые клетки.

Предпочтительно:

**Hex Grid**

Размер клетки:

примерно 20–30 метров.

Позже значение должно настраиваться через backend.

Каждая клетка имеет:

```text
id
hex_id
geometry
center_lat
center_lng
owner_team_id
owner_user_id
hp
max_hp
captured_at
last_activity_at
```

# 10. Механика маршрута

Во время активности сохранять GPS-точки.

Пример:

```text
RoutePoint {
    latitude
    longitude
    timestamp
    accuracy
    speed
    altitude
}
```

Точки сохранять локально во время активности.

Отправлять на сервер батчами.

Не отправлять каждую GPS-точку отдельным запросом.

# 11. Захват территории

Пользователь нажимает:

**БАСТАУ**

Создаётся activity session.

Пример:

```text
activity_id
user_id
team_id
started_at
ended_at
distance
steps
duration
average_speed
route
status
```

Пользователь начинает движение.

Приложение рисует линию маршрута.

Если маршрут замыкается, определяется polygon.

Далее определяется список hex-клеток внутри polygon.

Эти клетки захватываются командой пользователя.

---

# 12. Условие замыкания маршрута

Маршрут считается замкнутым, если пользователь:

приблизился к одной из предыдущих точек маршрута.

Например:

```text
distance <= 25 метров
```

Минимальный маршрут перед возможностью закрытия:

```text
300 метров
```

Минимальная площадь:

```text
1 000 м²
```

Значения вынести в конфигурацию.

---


# 14. Свободная территория

Свободные клетки:

```text
owner_team_id = null
```

Их можно захватить сразу.

---

# 15. Территория противника

Если территория принадлежит другой команде, использовать систему HP.

Пример:

```text
max_hp = 300
```

Новый захват:

```text
100 HP
```

Повторная активность своей команды:

```text
+20 HP
```

Максимум:

```text
300 HP
```

Если по клетке проходит противник:

```text
-20 HP
```

Если:

```text
HP <= 0
```

клетка становится захваченной новой командой.

---

# 16. Защита территории

Если участники команды продолжают ходить по своей территории, она становится сильнее.

Например:

```text
1 проход = +10 HP
```

Должен быть дневной лимит восстановления клетки.

Например:

```text
max +50 HP/day
```

Чтобы нельзя было искусственно фармить одну клетку.

---

# 17. Ослабление территории

Если территорию долго никто не посещает, она постепенно ослабляется.

Например:

после 7 дней без активности:

```text
-10 HP / день
```

Когда:

```text
HP = 0
```

территория становится свободной.

---

# 18. Утренняя механика

Берік Тұлға строится вокруг раннего подъёма.

Поэтому активности утром должны давать бонус.

Пример:

```text
05:00–06:00
x3 XP

06:00–07:00
x2 XP

07:00–09:00
x1.5 XP

09:00+
x1 XP
```

ВАЖНО:

множитель не должен увеличивать физическую площадь территории.

Он влияет только на:

- XP;
- рейтинг;
- награды.

Нельзя позволять человеку:

- телепортироваться;

```text
GPS
скорость

GPS accuracy
timestamps
```

# 21. Проверка скорости

Пример правил:

```text
0–10 км/ч
нормальная ходьба / бег

10–20 км/ч
подозрительно

20+ км/ч
не засчитывать захват
```

Но учитывать короткие GPS-скачки.

Не банить пользователя автоматически только по одной точке.

---

# 22. GPS teleport detection

Если между двумя последовательными точками пользователь переместился слишком далеко за слишком короткое время:

маршрут считать подозрительным.

Пример:

```text
1000 метров за 5 секунд
```

Такие точки необходимо игнорировать.

---

# 23. GPS Accuracy

Не учитывать точки с очень плохой точностью.

Пример:

```text
accuracy > 50 метров
```

Точное значение вынести в конфигурацию.

---

# 24. Автомобиль

Если пользователь начал идти, затем сел в автомобиль:

сегмент с высокой скоростью не должен участвовать в захвате территории.

Не обязательно завершать всю активность.

Просто исключить подозрительный сегмент.


Активность не должна пропадать.

GPS-маршрут сначала хранить локально.

После появления интернета синхронизировать.

Использовать очередь:

```text
pending_route_points
pending_activities
```

---

# 55. Battery Optimization

GPS сильно расходует батарею.

Нельзя записывать координаты каждую миллисекунду.

Использовать разумный интервал.

Например:

```text
каждые 3–5 секунд
```

или:

```text
каждые 5–10 метров
```

в зависимости от движения.

---

# 56. Background Tracking

Активность должна продолжаться:

- при выключенном экране;
- когда пользователь открыл другое приложение.

Но только если пользователь явно запустил тренировку.

Не отслеживать GPS пользователя постоянно.

Использовать:

Пользователь не должен иметь возможности самостоятельно изменить:

```text

team_score

```

через прямой запрос к Supabase.

Критичные расчёты выполнять server-side.

---

# 62. Territory Calculation

Расчёт захвата делать на backend.

Mobile отправляет:

```text
activity_id
route_points
steps
```

Backend:

1. проверяет маршрут;
2. запускает anti-cheat;
3. создаёт polygon;
4. определяет hex cells внутри polygon;
5. исключает запрещённые клетки;
6. рассчитывает capture / attack;
7. обновляет territory_cells;
8. создаёт territory_events;
9. рассчитывает площадь;
10. начисляет XP;
11. возвращает результат приложению.

---

# 63. Нельзя доверять клиенту

Flutter-приложение не должно отправлять:

```text
"I captured 25000 m²"
```

и backend не должен этому доверять.

Backend сам рассчитывает:

```text
route → polygon → cells → area
```

---

# 64. Realtime

Использовать Supabase Realtime для обновления территорий.

Если другой пользователь захватил территорию:

карта должна обновиться без полного restart приложения.

Но необязательно обновлять карту каждую секунду.

# 70. Требования к Codex

Перед написанием крупных модулей:

1. проанализируй текущую структуру проекта;
2. не переписывай существующий рабочий код без необходимости;
3. сохраняй Clean Architecture;
4. делай небольшие независимые модули;
5. не создавай огромные файлы;
6. выноси reusable widgets;
7. не хардкодь API keys;
8. используй `.env`;
9. создавай migrations для Supabase;
10. документируй нестандартную географическую логику.

После каждого большого этапа:

- запусти анализатор;
- исправь warnings;
- проверь build;
- проверь null safety;
- проверь Android;
- не ломай предыдущие функции.

Пользователь Берік Тұлға открывает приложение утром.

На карте он видит город, поделённый между командами.

**БАСТАУ**

Выходит на улицу.

Приложение начинает отслеживать движение.

За пользователем появляется игровая линия.

Он обходит несколько кварталов.

Возвращается к своей территории.

Контур замыкается.

Экран слегка вибрирует.

Территория внутри контура окрашивается.

Появляется:

```text
АУМАҚ АЛЫНДЫ

+18 420 м²

5 843 қадам

+245 XP
```

Командная статистика Берік Тұлға обновляется.

Пользователь видит:

```text
Берік Тұлға

Қызылорда

12.4 км²
```

На следующий день он просыпается и хочет расширить территорию ещё дальше.
