# Архитектура записи прогулок и захвата территории

`core` содержит конфигурацию, общие сервисы, тему, локализацию и форматирование. `features` разделяет auth, map, activity, profile, teams, leaderboard и achievements. `shared/widgets` содержит повторно используемые элементы интерфейса.

Модели и правила маршрута находятся в `activity/domain`. Интерфейс `ActivityRepository` отделяет сохранение от UI. `activity/data` реализует GPS, системный шагомер и локальное сохранение с Supabase-синхронизацией. Riverpod controllers/providers связывают данные с presentation. Карта получает обычные RoutePoint и не вычисляет владение территорией.

## География

- Кызылорда: 44.8488° N, 65.4823° E. GeoJSON принимает **longitude, latitude**, а MapLibre `LatLng` — **latitude, longitude**. Модели и RPC называют обе координаты явно.
- Расстояние на клиенте — Haversine, радиус Земли 6 371 008,8 м. Сервер использует PostGIS `ST_Distance` по `geography` WGS84. Значения могут немного различаться из-за сферического и эллипсоидального расчётов.
- `geometry` хранится в EPSG:4326. Сервер создаёт hex-сетку в UTM 41N (EPSG:32641), площадь считает по `geography` WGS84. Клетки включаются, если их центр внутри валидного контура; площадь начисляется целыми игровыми клетками. Запрещённые зоны по-прежнему проверяются на пересечение со всей клеткой.
- Сторона/circumradius клетки — 25 м; ключ `utm41-25-i-j` фиксирует одну сетку для Кызылорды. Это трактовка параметра size в [ST_HexagonGrid](https://postgis.net/docs/ST_HexagonGrid.html). Изменение размера требует отдельной миграции сетки. Существующие `is_playable=false` не включаются генератором.
- Замыкание до любого участка пройденной линии — 25 м, минимум пути внутри контура — 100 м; пересечение между GPS-замерами обрезается в точке замыкания, минимум полигона — 1 000 м². Сервер отклоняет самопересечения, разрывы, контуры вне границ встроенной карты и площадь свыше 2 км². Решение UI не является основанием для онлайн-владения.
- `territory_restrictions` содержит 418 геометрий из OSM: вода, waterways с буфером 8 м, железная дорога 20 м, motorway/trunk 12 м. Сетка не захватывает пересекающие их клетки. Это маска из имеющихся данных, а не полная проверка всех ограничений города; дополнительные зоны добавляет администратор. Генератор: `tools/build_territory_restrictions.py`.

## Непрерывность маршрута

Каждая исходная точка сохраняет точность, время, скорость, высоту и признак mock. Клиентский accepted — только для предварительного отображения. Сервер игнорирует присланные accepted/segment_start и вычисляет их заново.

Точка исключается при accuracy > 50 м, mock, скорости > 20 км/ч, невалидных координатах или нерастущем времени. Также проверяется скорость между соседними координатами. После плохого сегмента следующий валидный участок получает новую стартовую точку. При разрыве > 60 с не рисуется соединяющая линия и не добавляется вымышленное расстояние. Один скачок не блокирует аккаунт и не прекращает всю прогулку.

Эти эвристики отсекают очевидные ошибки, но сами по себе не доказывают подлинность GPS или шагов. Захват использует только принятые непрерывные сегменты. Сервер сохраняет `reported_steps`, оставляя проверенные steps и XP нулевыми; `captured_area` рассчитывает из клеток. Play Integrity/App Attest и доверие датчикам остаются следующим этапом.

## Транзакция захвата

`append_activity_points` сначала вызывает закрытую функцию GPS-валидации, затем обрабатывает новые endpoints и возвращает `CaptureResult`. `capture_processed_seq` и уникальный индекс события `(activity_id,cell_id)` предотвращают повторные capture/attack/defend в одной прогулке. Свободные клетки получают 100 HP, свои +20 (не более +50 за местный день Asia/Qyzylorda), чужие −20 с передачей при нуле. Заблокированные клетки и маска исключаются повторно даже для существующей сетки. Владение, события, площадь активности и агрегаты команды/владельца изменяются в одной транзакции. `finish_activity` сохраняет завершение и возвращает тот же результат без повторного захвата.

`features/territory` содержит модель результата, отдельную демонстрационную геометрию и карточку UI. Демо использует метрическую проекцию относительно центра города и отдельные ключи `demo-25-q-r`; не отправляет площадь в облако. Его площадь может немного отличаться от серверной сетки UTM. JSON checkpoint хранит клетки и результат; старая история без поля capture читается с нулевой площадью. Acknowledgement не заменяет более новый результат устаревшим ответом сети.

`RouteMap` рисует захваченную арену непрерывной заливкой цвета команды с opacity 0.55. Обводка отдельных клеток удалена, antialias заливки отключён, чтобы соседние клетки не разделялись швами. Улицы и маршрут остаются видны. Онлайн RPC `get_territory_cells` принимает viewport, ограничивает регион Кызылордой и возвращает до 2 000 клеток без user IDs или маршрутов. Realtime-события таблицы teams вызывают повторную загрузку viewport; приватные GPS-точки не публикуются. Экран завершения наблюдает сохранённую активность и обновляет захват после возвращения сети.

## Offline и синхронизация

Checkpoints записываются в одну сериализованную очередь SharedPreferences с отдельным ключом для каждого пользователя. Хранятся исходные точки, текущая сессия и история. Для первого этапа это небольшой локальный журнал; перед длительными полевыми испытаниями следует заменить реализацию repository на SQLite/Drift с отдельной таблицей точек, чтобы не переписывать весь JSON на каждом checkpoint.

Точки отправляются RPC батчами по 100. Первичный ключ `(activity_id, seq)` делает повтор безопасным. Сервер блокирует строку сессии на время добавления/завершения. Завершённая сессия не начисляет результат повторно. Acknowledgements объединяются с последним checkpoint внутри очереди записи: ответ сети не может стереть новые GPS-точки или отметку завершения.

При появлении сети очередь повторяется каждые 30 с и при app resume. После завершения pending-записи сохраняются. Первичная серверная синхронизация принимает offline-сессии до 7 дней; более старые маршруты остаются локально и требуют отдельного решения по сроку хранения/импорту. История первого этапа загружается с устройства; облачное восстановление истории после переустановки ещё не реализовано.

При уничтожении процесса ОС сохраняется последний записанный checkpoint. При следующем запуске приложение предлагает завершить восстановленную запись. GPS не запускается сам.

## Безопасность и приватность

RLS скрывает профиль, маршрут, дневную статистику и достижения от чужих аккаунтов. Права UPDATE профиля ограничены именем, username, фото, городом, полом и датой рождения. Доступ к игровым полям, бану и членству возможен только через контролируемые функции/администратора. Таблицы территорий, событий и ограничений закрыты для прямого доступа клиента; карта получает безопасный GeoJSON через RPC.

Командный RPC возвращает только имя и username участников. Storage разрешает запись аватара только в папку `auth.uid()`. Аватары публичны; маршруты не отправляются в публичное хранилище.

Публичное распространение маршрутов отключено. Перед его добавлением нужно обрезать начало/конец по **метрам вдоль маршрута**, не по числу GPS-точек, применить privacy zones server-side и отдельно проверить видимые координаты карты на share card.

## Android toolchain

Онлайн-вход выполняется через Supabase `signInWithPassword` по email и паролю существующего аккаунта. Самостоятельная регистрация закрыта в настройках Auth; пользователей создаёт владелец проекта в Dashboard с `Auto confirm user?`. Триггер Auth создаёт профиль. После успешного входа экран перечитывает профиль и закрывается; пароль очищается и не записывается в SharedPreferences. Supabase Flutter сохраняет и обновляет сессию. Неверные данные дают общее сообщение без раскрытия существования аккаунта. Восстановление пароля пока выполняет администратор.

Используется AGP 9.1.0, Gradle 9.3.1, Kotlin 2.4.0, compile SDK 37, JDK 21. Flutter оставляет legacy Kotlin через `android.builtInKotlin=false` для совместимости с плагинами. Health удалён, шагомер использует `pedometer 4.2.0`. Mapbox заменён MapLibre 0.27.1; прежний compatibility callback удалён. MapLibre самостоятельно поддерживает смешанный Kotlin-режим. Зависимости Pub не модифицируются.

## Карта и локальный GPS

MapLibre рисует встроенную геометрию OpenStreetMap. `assets/maps/kyzylorda.geojson` содержит 51 444 объекта и занимает 12,3 MiB до сжатия APK. Стиль, пять диапазонов Noto Sans и лицензии также входят в assets. Android/iOS при первом запуске копируют геометрию и glyphs в application support; идентификатор каталога зависит от хешей всего пакета. Повторный запуск проверяет размеры файлов, а незавершённые копии записывает заново через `.part`. Стиль указывает только `file://` ресурсы. Web читает эти же файлы с текущего origin; нативный APK работает без HTTP-сервера.

Геометрия маршрута создаётся как GeoJSON LineString для каждого непрерывного участка и обновляется через существующий source, без удаления/создания всех аннотаций на каждом fix. Маркеры также обновляются одним source. История использует bounds всех принятых точек. Ручное движение карты отключает follow; «Моё местоположение» включает его снова. Собственный GPS картографического SDK отключён. Вне подготовленной области города показывается пояснение; запись GPS не блокируется.

В widget tests подменяется только platform/WebGL surface через `mapSurfaceProvider`; native integration test запускает реальный MapLibre. Геометрия и координатный порядок проверяются отдельно.

Веб-превью использует локальный MapLibre GL JS 6.4.1 в `web/vendor/maplibre/`, включая shared-модуль, worker и CSS. `main.dart` задаёт `MapLibreJsSource.urls` на текущий origin, CanvasKit также обслуживается локально. Браузерному превью нужен локальный HTTP-сервер; APK использует встроенный нативный движок.

Локальный режим имеет профиль `local` и отдельный журнал `activities_v1_local`; Supabase-клиент отключён. Поле `synced=true` у таких записей означает завершённую локальную запись, сетевые RPC не вызываются. `OFFLINE_ONLY=true` по умолчанию отключает инициализацию Supabase; главный путь входа — прогулка без аккаунта. Команды/общий рейтинг объясняют ограничение офлайн-версии. Android release сохраняет разрешение `INTERNET`. Для онлайн-сборки нужны `OFFLINE_ONLY=false`, публичные настройки Supabase и `--dart-define-from-file=.env`; скрипт `run.ps1 -Online` проверяет конфигурацию до запуска.

`path_provider_android` 2.2.23 и `path_provider_foundation` 2.5.1 закреплены на платформенных реализациях через каналы. Новые JNI/ObjC hook-сборки в текущем Flutter SDK на Windows останавливаются на отсутствующем `hook.dill.d`; исходники зависимостей не изменяются.

Подробности адаптации GPS из MIT-проектов: [gps-research.md](gps-research.md).

## Шагомер

`StepsService` запрашивает Android activity recognition / iOS motion permission. После запуска прогулки отдельная подписка `Pedometer.stepCountStream` читает системный счётчик, а `WalkStepCounter` вычисляет прирост от первого показания. Пакет возвращает накопительный счётчик на обеих платформах. Дубли и уменьшения не меняют итог; новая прогулка создаёт новую базу. UI обновляется по событиям, без опроса Health и без оценки шагов из GPS.

Каждый прирост сохраняется в той же очереди repository, что и GPS. При завершении или dispose подписка отменяется; восстановленная сессия сохраняет последний итог и не запускает датчик самостоятельно. Поле `health_available` оставлено в старом JSON для совместимости и теперь означает получение показания от шагомера. Ошибка датчика не блокирует GPS; не полученный итог остаётся `null`.

Границы измерения зависят от доставки событий ОС: первое показание задаёт базу, финальный результат содержит только доставленные события. Android допускает задержку счётчика до 10 секунд. Нужны полевые испытания, особенно коротких прогулок и заблокированного экрана. Источники и сценарии: [pedometer-research.md](pedometer-research.md).
